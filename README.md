# Внутренний marketplace объектов недвижимости

Каталог объектов агентства с фильтрацией уровня CIAN и 3D-туром в карточке. Инструмент
внутренний: открытой регистрации нет, клиент получает от агента ссылку на объект или
подборку.

- Что и зачем строим — [docs/PRD.md](docs/PRD.md)
- Модель данных и полная спецификация фильтров — [docs/DOMAIN.md](docs/DOMAIN.md)
- Принятые решения — [docs/adr](docs/adr)
- Дизайн-система (Airbnb) — [design-md/DESIGN.md](design-md/DESIGN.md)

## Запуск

```bash
npm install
npm run dev
```

Каталог откроется на http://localhost:3000/catalog.

### Пока нет Postgres

Добавьте в `.env` строку — каталог заработает на демо-объектах из
`src/lib/demo-data.ts`, и в шапке появится плашка «Демо-данные»:

```
USE_DEMO_DATA="1"
```

Флаг явный сознательно: молчаливый откат на выдуманные объекты в приложении для
риэлторов не должен быть возможен — отличить его от настоящей выдачи нельзя.

### С Postgres — это нужно, чтобы заводить объекты

Демо-режим только показывает каталог. Вход и заводка объектов работают лишь с базой.

```bash
docker run -d --name realty-pg -p 5432:5432 \
  -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=realty postgres:17

npm run db:migrate    # создаст схему приложения и применит миграции
npm run db:seed       # администратор и справочники городов
npm run db:generate   # перегенерирует клиент после правок schema.prisma
```

Уберите `USE_DEMO_DATA` из `.env` — приложение начнёт читать базу.

**Таблицы живут в отдельной схеме `realty`, а не в `public`.** База может быть общей
с другим сервисом, и тогда `public` превращается в свалку, где чужая миграция способна
задеть наши таблицы, а наша — чужие. Схема создаётся сама перед миграциями (`db:setup`
вызывается внутри `db:migrate` и `db:deploy`), имя переопределяется переменной
`DATABASE_SCHEMA`. Параметр `schema` в `DATABASE_URL` перезаписывается сознательно:
забытый `schema=public` не должен тихо разложить таблицы в общую схему.

Сиды создают администратора. Email берётся из `ADMIN_EMAIL` (по умолчанию
`admin@agency.local`), пароль — из `ADMIN_PASSWORD`, а если его не задать,
генерируется и печатается **один раз**: в базе лежит только хеш.

`DATABASE_URL` берётся из `.env`, строку подключения читает `prisma.config.ts`.

## Что уже работает

- **Вход по логину.** Сессия в базе, в cookie только случайный токен. Отключили
  пользователя — его сессия умирает на следующем запросе. Открытой регистрации нет.
- **Заводка своих объектов.** Форма с проверками: этаж не выше этажности, жилая
  площадь не больше общей, ссылка на тур проверяется на месте. Черновик
  сохраняется неполным, публикация требует цену, площадь, город и улицу.
- **Свои объекты и статусы.** Агент видит и правит свои, админ — любые. Статусы
  от черновика до проданного, удаление мягкое, изменения пишутся в журнал.
- **Каталог:** серверная фильтрация, сортировка, пагинация, состояние в URL.
- **3D-тур в карточке** с allowlist доменов и CSP `frame-src` из того же списка.

города и ЖК до появления интерфейса добавляются в базу напрямую.

## Деплой на Render

Сервис заводится руками в панели. `render.yaml` в репозитории сознательно нет:
тариф, переменные и тип сервиса живут в панели, а файл в репозитории лишь создавал бы
иллюзию источника правды.

**New → Web Service**, репозиторий `QAway-to/mvp-realty-marketplace`, ветка `main`.

| Настройка | Значение |
|---|---|
| Runtime | Node |
| Build Command | `npm ci && npm run build` |
| Start Command | `npm run start` |
| Node version | берётся из `.node-version` (22) |

`prisma generate` запускается сам: он прописан в `prebuild`, потому что
сгенерированный клиент в репозиторий не коммитится.

**Переменные окружения:**

| Переменная | Когда нужна |
|---|---|
| `DATABASE_URL` | Internal Database URL от Render Postgres |
| `DATABASE_SCHEMA` | Необязательно. По умолчанию `realty` — таблицы не в `public` |
| `USE_DEMO_DATA=1` | Пока Postgres не привязан — сервис поднимется на демо-объектах |

Порт Next берёт из `PORT`, который Render задаёт сам.

**Миграции.** После привязки Postgres примените схему — `npm run db:deploy`
(одноразово через Render Shell или как Pre-Deploy Command). Затем уберите
`USE_DEMO_DATA`, и каталог начнёт читать базу.

Деплой идёт автоматически на push в `main`.
